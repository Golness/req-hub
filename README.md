# ReqHub

DeepSeek Harness 插件。

## 第二阶段架构边界

Client 的 Host 请求统一经 `src/client/api/`：端点目录负责 URL 与参数编码，JSON 接口保留
HTTP 状态、错误码、详情和完整响应，文件预览保留转换警告，SSE / NDJSON 共用 UTF-8
流读取与取消清理。需要区分 404 / 409 / 410 或 JSON / SSE 的调用仍可读取原始 Response。
不自动重试写操作，不自动翻页；会话版本、范围和分页游标仍显式传递，失败不静默截断结果。
流的单条完整记录默认限制为 8 MiB，超限明确失败。HTTP 200 的失败任务记录仍是有效数据。

入口只向 React 传递当前会话 ID 的 getter / subscription，不再暴露全局 Host ctx。
Skill 预览随会话变化取消旧请求；文件预览、目录查询和会话流由各自组件持有取消信号。
`SyncPanel` 拆为准备与执行 hook、快捷同步、进度、历史和会话预览；`ContextAssist` 拆为
任务 hook、设置、状态、结果和相关资料视图；`DocsViewerBody` 的目录恢复、创建状态和
当前会话定位已抽为 hooks 与 API 用例。隐藏标签、设置草稿和现有共享控件继续保留。

同步、编写和 Knowledge V2 的完成提醒在 Host 发布子会话身份后注册到该 Agent 的 ctx，
运行时与 Agent 共同持有清理责任。旧适配器没有 Agent ctx 时保留按精确会话身份过滤的
回退。`llm/stream` 不属于 Agent scoped event，`session/event` 使用 Session 的路由身份；
这些监听保留归属检查、guard、restrict 和未处理请求的 `next()`，不机械迁到 Agent ctx。

`req-hub.sync-session-facts` 是 Host-only 的纯同步投影试点，版本为 1：从已提交事件重建
压缩标记与最近一轮失败，不新增业务事件，也不替换任务数据库。每日同步的 30 秒短期唤醒
通过可选 `timer` 注入使用 `ctx.timeout()`；服务缺失时回退到原生可撤销定时器，关闭仍等待
在途批次。契约按相邻 DSH `4878cdabd8` 源码核对，并使用其已构建包做隔离组合测试。

保留的 UI 轮询查询持久化任务、队列和报表，不以 Agent 状态判断某次执行完成：任务观察
收到终态、删除或卸载即停止，断网退避至最多 30 秒；增强与编写在执行期间查询，失败后
间隔 3 秒，终态停止；报表只在存在活动任务时查询。壳层总览还负责发现新任务，因此终态后
继续低频查询（6 秒，活动时 1.5 秒），焦点和本地变更事件立即刷新，卸载取消请求并清理监听。

第二阶段同时修复回归暴露的知识库入口、飞书诊断翻译与名称 / 范围 / 页码占位符问题；
旧文案选择器、已更名标签 ID 和不完整接口替身按当前契约更新，保留原有行为断言。
真实用户 profile 的安装启用、HMR、主题、窄面板、键盘和外部账号发布仍需真实宿主验收。

## 第一阶段架构边界

配置、Knowledge V2 和 phased-sync / sync-retry 已提供独立于 HTTP 的应用入口，
位于 `src/server/application/`。UI 的认证 HTTP 入口、Agent 操作目录与每日同步调用同一实现；
quick-sync 进度在应用层传递结构化事件，由 HTTP 适配器编码为 SSE，工具返回结构化终态。
实际 Agent 的工作区归属在同步与知识库入口验证，不能通过请求参数选择其他会话的权限。
其余文档树、创建、编写、增强、日志及其他旧入口暂保留 `operations.js` 的 HTTP 兼容适配，
不代表所有路由已完成应用层迁移。原有 action 名、URL、任务 ID 与存储格式保留。

每次插件激活创建独立的 `ConfigRepository`；经 `repository.run()` 绑定 HTTP、工具和后台任务，
旧 `loadConfig` / `saveConfig` 调用沿用当前异步作用域，生产激活不再修改模块级 profile 配置。
所有写入口进入同一实例队列：新更新从最新值合并，旧快照保存合并未冲突字段，同字段冲突返回
`CONFIG_CONFLICT`。GET /config 提供 `_revision`，提交时可携带该版本拒绝陈旧保存。
部署配置覆盖字段在写入时拒绝被设置页覆盖，返回 `CONFIG_DEPLOYMENT_OVERRIDE`；
配置保存后刷新失败返回 `CONFIG_APPLY_FAILED` 和 `saved: true / applied: false`，不报告已应用。
原子写使用同目录临时文件；队列与快照并发保护限于本 Host 实例，不提供跨进程文件锁。

Host 在初始化前建立生命周期所有者，失败时等待回滚；卸载先注销入口、取消全部生产者，再逆序
等待关闭资源。被撤销的同步响应可以先结束，底层执行仍被持有并在卸载时等待，旧回调不能重新
取得执行所有权。Client 的 CSS 在构建时收集为清单，由激活 effect 安装、引用计数及清理，
包含懒加载视图的样式；模块工厂不再向 DOM 注入 CSS。

回归使用服务边界与故障测试，构建后运行 `npm run verify:package`：该检查包含隔离安装解析、
工厂无 DOM 副作用、激活样式完整、重叠激活及卸载清理。组合测试使用本地 DSH 包，不等于
真实用户 profile 的安装、HMR、主题与窄面板验收；部署前仍须按实际宿主复核。

## 界面约定

ReqHub 品牌标识使用原创的 RH 连字徽标，以蓝色连接段表达资料汇聚。几何定义统一位于 `src/shared/brand.cjs`，标签页和插件入口通过 `IconReqHub` 渲染；徽标主体及连接段使用宿主前景色、业务色 token，随实际主题自动调整，不根据操作系统主题猜测 DSH 设置。发布包的 `icon.svg` 为跨背景可用的蓝色版本。明暗主题 SVG 与尺寸预览位于 `docs/brand/`。

开发界面前阅读 [UI 与布局规范](docs/ui-guidelines.md)，通过共用组件实施规则，运行 `npm run check:ui` 检查。

界面说明使用简短文案，避免重复字段信息及内部流程解释；保留必要限制、失败原因和处理方法。
设置页统一使用 `SettingsActionBar`：页面保存位于固定底栏右侧；局部操作位于所属分区末尾右侧。
所有设置标签使用同一内容宽度和字段标签列，不为连接区、目标区或单个依赖另设窄栏；内容与固定底栏预留相同滚动条空间，保持操作按钮右边缘对齐。
保存、应用配置、绑定等提交操作用主按钮，检测、刷新和解除绑定用描边按钮；同行时检测在前、提交在后。
保存与检测使用默认按钮尺寸，列表行和工具栏使用小号按钮。操作提示位于左侧，窄面板允许换行。
切换设置标签时仅显示当前标签的底栏；自动保存的开关和下拉选择仍就地反馈，不增加重复保存按钮。
记录类列表统一使用平面行和行间分隔线，去掉记录卡片的底色、圆角、阴影和外围边框。
行高随内容自适应，分页固定在底部，默认每页 10 条，可选 10、20、50 条；
记录超出可用高度时在列表内滚动，分页底栏展示页数并支持输入页码跳转，翻页替换当前记录，
双列会话列表撑满剩余高度，选择统计与导入操作保留在面板底部；窄列中的翻页按钮成组换行。
不再用「加载更多」持续向下追加。覆盖 Wiki 页面、资料、问答、检查、任务报告、
搜索、会话选择与管理、同步历史和知识关联记录。点击记录查看详情或跳转，不另设右侧箭头；
记录内的独立操作保留原有行为。游标列表展示已加载页数，可跳转已加载页面，下一页按需读取后续记录。
浏览历史页时暂停实时列表刷新，防止阅读位置跳动。目录树保持原有层级、展开收起和滚动方式。
列表详情弹窗提供标题、关闭按钮和独立滚动正文；点击遮罩或按 Escape 关闭一次即返回列表，关闭点击不会触发行操作。
新建需求目录按 Git 状态、需求信息、创建预览及底部操作分区。main/master 的更新入口始终展示；工作区有改动、Git 操作未完成或不在仓库根目录时禁用并说明原因，处理后可刷新状态。更新仍只允许干净工作区快进合并。

设置页按“通用”“依赖配置”“同步计划”“知识库”“Prompt 管理”拆分标签，使用与日志页一致的
下划线导航及右侧关闭按钮，不再显示“设置”标题栏。切换标签保留未保存内容。
表单使用宿主字体，缺少字体变量时回退到系统无衬线字体。通用与 Prompt 共用页面保存操作；
同步计划的保存由页面底栏承接；依赖配置与知识库按独立子页签各自保存，操作固定在底栏。
知识库分为“自动整理与每日更新 / 整理规则 / 清空知识库”，飞书分为“连接 / 发布位置 / 资料副本”；切换保留草稿，隐藏页签不显示操作。
索引任务、连接凭据与分发记录按需在弹窗展示，长内容滚动时保留弹窗操作栏。应用日志主列表占满剩余高度，结构化日志通过详情弹窗完整查看。
知识库设置只在「设置 → 知识库」中提供，
知识库功能页不再有齿轮入口；在那里保存规则或清空知识库后，已挂载的 Wiki 与资料视图同步刷新。
「通用」集中设置时区、默认用户名、模型、共享子代理并发、模型执行超时和知识处理大小上限。`general.timeZone` 为唯一时区配置，默认 `Asia/Shanghai`（北京时间），支持搜索 IANA 时区。
时区、用户名和模型直接展示；并发、超时和知识处理上限收进“高级设置”，各字段说明通过信息提示查看。
默认用户名仍统一存储在 `defaultUsername`，同时用于新建功能和定时同步；同步计划页只显示已保存的用户名，不再编辑或提交它。
`general.taskTimeoutMs` 统一约束同步、编写、知识库整理和知识关联的单次模型执行，默认 20 分钟，范围 30 秒–60 分钟；排队不计时。设置页使用秒，存储保持毫秒。已有显式配置保留，升级不会覆盖已保存的 5 分钟配置。
知识库整理与知识关联共用 `general.knowledgeMaxInputBytes`（默认 2 MB，范围 1 KB–20 MB）和 `general.knowledgeMaxResultBytes`（默认 250 KB，范围 1 KB–1 MB），按完整封装计量。设置页使用 KB（1 KB = 1000 B，1 MB = 1000 KB），存储及协议字段保持字节。同步和编写继续按模型上下文预算控制。
同步分析报告和变更清单各允许 256 KB，分块分析与汇总使用同一上限；汇总清单同样声明上限，超限错误包含实际大小与上限，不截断变更。子代理沿用宿主的输出 token 配置，插件不再固定覆盖为 8000 token。完整输出仍须满足模型上下文预算，不能靠增加容量绕过模型限制。同步准备上限为 20 分钟，无进度上限为 65 分钟，覆盖可配置的最长单次模型执行；整个任务上限仍为 6 小时。读取页数随模型上下文增长，最多 1024 页，显式配置范围为 8–1024 页；每页仍受完整封装和模型上下文约束。分页大小、重试次数、并发数量与解析解压上限保留，分别用于控制上下文开销、无效修复、资源占用和输入膨胀。
旧 `wiki`、`enhancements` 的 `timeoutMs`、`maxInputBytes`、`maxResultBytes` 以及 `ai.delegation.timeout` 不再生效，保存时直接移除，不迁移旧值。CLI、代码索引的超时、各类数据保留规则和任务准入数量语义不同，继续独立设置。
插件显示的索引、文件、日志、会话、版本、Wiki 与同步时间均按已保存时区格式化，保存后已打开的界面立即更新；今天与新建功能默认日期也按此时区计算。
知识库每日同步与同步计划每日任务共用 `general.timeZone`，只保留各自的执行时分；旧的 `dailyUpdateTimeZone` 被忽略并在保存时移除，不迁移独立时区。
时区变更后重新装载两类定时计划；时间戳持久化和协议字段仍保留绝对时间，已有需求分支名称中的日期不变。
“文档关联与检查”总开关位于“设置 → 依赖配置 → GitNexus”，修改后自动保存，独立于代码索引的其他操作。
「依赖配置」中的 GitNexus 复用同一套表单与说明浮层，按 MCP 连接、代码索引纵向分组；服务选择与工具注册归属 MCP 连接，索引状态及操作归属代码索引；当前代码任务在独立“当前任务”分区展示。修改配置后自动保存。设置页仅展示当前代码刷新或索引更新任务的进度、取消与执行日志，不混入其他增强任务历史；文档助手中的任务历史仍可回看检查与关联结果。插件所有 Select 下拉菜单（含搜索菜单）均与触发框等宽、左侧对齐，靠近窗口边缘时按可见区域收缩和避让。
“检查索引状态（MCP）”只读查询索引状态，不刷新文档代码关联，也不运行本地 CLI；
“更新本地索引”单独运行本地分析，完成后核验 MCP。两个入口始终展示，与文档关联开关独立；任务执行期间暂不可再次启动。
GitNexus 状态未检查时显示“尚未检查”，不再沿用文档关联图的“未启用”。
“当前任务”按任务名称与状态、执行阶段、真实进度及折叠日志组织，取消入口位于任务标题行。
索引任务仅在收到真实百分比时显示进度条，否则展示执行阶段和等待说明。设置中的执行日志默认折叠，使用标题旁箭头展开；阅读区高度稳定，后台更新不自动展开或跳转阅读位置。

## 快捷同步

“依赖配置”下设“GitNexus”和“飞书 CLI”二级标签，各自展示独立配置页。
默认打开 GitNexus，首次访问时加载对应配置；切换依赖或设置标签保留未保存内容与任务状态。
飞书页面按“CLI 连接”和“发布目标”分区，以轻分隔线区分操作范围。
发布目标提供“默认知识库 · 全部工作区”和“单工作区绑定”两种模式：默认模式仅显示知识库选择、
影响范围及批量保存，工作区清单默认折叠；单工作区模式显示工作区、已有绑定及层级浏览器。
知识库使用可搜索下拉选择，游标分页支持前后翻页和已选项回显；刷新入口紧邻选择框。
连接检测与应用凭据检测的结果分别保留在对应分区；应用配置与登录默认折叠在连接配置内，
检测范围及发布限制收进标题旁的说明提示。
GitNexus 页面保留 MCP 连接、代码索引和当前任务状态；飞书 CLI 页面
可保存 CLI 原生程序路径、应用配置名称、调用身份及命令超时。
“工作区推送目标”读取 DSH 已登记的全部工作区，选择工作区和文件夹或知识库类型后，
通过飞书 CLI 按层级加载可选目标。文件夹逐级进入；知识库先选择空间，再逐级选择页面节点。
选择操作分别显示“选择当前文件夹”和“选择当前节点”，知识库节点作为推送父位置。
发布目标选择“默认知识库 · 全部工作区”时，仅需选择知识库空间；点击“保存全部工作区”后，
Host 读取 DSH 登记的全部工作区，逐一分页检查该空间的一级节点，精确匹配各工作区名称，
存在则复用，不存在则创建同名 docx 页面。全部节点准备成功后，一次保存各工作区的目标绑定。
默认模式会更新所有已登记工作区的绑定，不受顶部单个工作区选择限制；保存前展示工作区名称及总数。
“查看工作区列表”按工作区、本地目录、已绑定飞书目录（知识库或文件夹）和操作分列展示，支持分页和逐行解除绑定。
表格随设置面板宽度展开，每页按内容高度展示；长路径省略显示，悬停可查看完整路径和远端地址。
单工作区模式下，已绑定工作区只展示绑定摘要和解除操作；解除成功后才展示目标类型、目录选择和保存绑定。
列表从 Host 读取实际保存的绑定，未绑定和本地路径变化分别标记；解除绑定只移除该工作区的本地配置，不调用飞书删除接口。
解绑失败保留原行；绑定已被其他操作修改时先刷新列表，避免覆盖新绑定。解绑成功同步更新批量绑定版本，随后仍可保存全部工作区。
已有知识库绑定会回填可选的知识库；默认模式的知识库选择独立于当前工作区，保存后或切换工作区时保留，
允许继续批量保存。刷新工作区列表后可为新增工作区补建节点；更换 CLI 连接时清除旧选择，重新加载该连接下可用的知识库。
多个同名一级节点或 DSH 工作区重名时停止并明确提示。重复保存先检查已有节点。
创建前检查整个工作区集合、实际路径、连接配置及全部绑定版本，失败保留本次操作前的本地绑定；
若中途失败，显示已准备及新建数量和失败工作区，说明远端可能保留已创建节点，重试复用已有节点。
默认模式仅创建作为父位置的一级页面，不推送业务文档；解除绑定仅清除当前工作区绑定，不删除远端页面。
面包屑与返回上一级支持切换层级，每次仅加载当前层级，分页按需读取；选定位置显示完整路径后保存绑定。

只有远端节点验证与本地绑定保存均成功才显示完成；批量绑定入口本身不上传本地文档正文。

### 新资料的本地文件与飞书副本

定时任务报告按实际来源／分发条目统计，不把工作区汇总重复计数；成功、失败、跳过／警告和待处理分别展示，并按独立编译任务归并失败原因。同一来源版本的后续编译不会改写其他任务报告。Codex 会话发现排除原文件已不存在的索引记录，只给出带数量的警告，不修改 Codex 数据。会话增量导出支持持久化轮次记录的重复／部分合并，并保留旧轮次正文；未变化的有效来源仍参与下次编译检查，以便恢复上次失败。

知识页面的内容、引用和版本校验在提交工具返回成功回执之前执行，模型可在当前步骤纠正；原有校验与发布条件保持有效。首次发布或旧发布缺少／滞后摘要时，编译会补齐有效来源。单次模型执行超时默认额外重试一次，`knowledgeV2.modelRetryCount` 可设置为 0–2；取消、预算超限和非法输出不盲目重试。历史报告保留真实失败，不会因代码修复被批量改为成功。

四类资料统一保留工作区 `docsDir` 下的正式文件：用户放入的任意格式文件、同步生成的需求／技术方案、同步成功的会话，以及写作保存的文档。会话同步新增 `docs/sessions/<稳定身份>.md` 导出，包含来源、会话身份、源版本和完整文本；每日会话同步使用同一导出逻辑，不把任务 `input/sessions` 当作正式资料。已有导出被用户修改时报告冲突，保留用户文件，不覆盖；来源会话始终只读。

「设置 → 飞书 → 工作区资料副本」中的自动同步开关默认关闭，由用户明确启用，作用于所有已登记工作区的 docs。启用时仅建立文件元数据基线，不读取正文或回填历史文件；此后新增或实际修改的文件经两次稳定发现后登记。ReqHub 保存产生的正式文件可直接登记，生产者与后台发现按内容 hash 去重。Host 未运行时不执行任务；重启后通过持久化基线识别新增／修改文件。关闭期间的变化不在重新启用时回填。

本地文件先保存，飞书失败不会撤销本地文件或重跑生成任务。独立的 `document-replicas.sqlite` 保存分发元数据、失败和恢复状态，不建立知识索引，也不导入 OpenViking。上传使用有界内存快照并校验文件读取前后的身份与版本。任意格式保留原扩展名，Markdown 使用原生 Markdown 创建，其他格式使用原附件上传。远端位置为 `<绑定父位置>/<docsDir>/<相对目录>/reqhub-versions/<文件路径摘要>/<内容摘要>/<原文件名>`；每个内容版本独立保存，避免缺少原子版本条件的覆盖接口损坏远端编辑，不自动删除旧版本。

默认每 10 秒发现文件、单文件上限 100MB、每工作区最多发现 100000 个文件；可通过有效的 Cordis Config 中 `documents.scanIntervalMs`、`maxFileBytes`、`maxFiles` 调整。超限报告明确错误，不截断后标成功。飞书未配置／失败保留待处理项并退避重试，界面可刷新状态、查看最近成功链接并仅重试飞书；上传响应丢失且无法证明结果时标记待核实，不盲目覆盖或重复创建。本地删除保留远端副本。插件卸载取消并等待分发退出后关闭控制库。

自动资料同步开启时，每日快捷同步不再额外调用原两文档飞书推送，避免重复发布；未开启时保留原手动／定时推送行为。新的状态查看与重试由同一 Host 逻辑供认证 UI 和工作区受限 Agent 操作使用；自动外发授权和配置只能由用户修改。

同步历史统一由顶部「同步历史」页签进入，保留类型筛选、版本对比、任务详情及删除操作。
历史页按「版本对比 / 执行记录」分区，类型筛选统一作用于两者；版本选择等宽，操作单独对齐。版本菜单与选择框同宽对齐，圆角、间距及浮层材质遵循 DSH 规范。
「查看差异」直接打开只读对比并保留返回焦点；记录的详情和删除操作分组，存储清理默认收起。
历史记录的「查看详情」与重试操作在右侧相邻，删除操作在左侧独立分组；步骤重试位于标题操作区，窄面板下换行对齐。
同步与设置共用操作栏和按钮语义：启动、保存用主按钮，查看与刷新用中性描边，重试用蓝色，停止任务用警示色，删除用危险色，均随宿主明暗主题变化。
没有额外信息的步骤不提供展开。进度默认展示用户可读的范围与结果；分析任务详情按文件、会话摘要和技术信息分组，完整保留所有条目，长列表滚动增量展示。任务短列表不分页，历史不足一页时隐藏分页；常驻进度通知不重复提供删除入口。
「删除本次记录」仅清理一次执行；「删除任务全部记录」清理同一任务的所有执行（含重试）。两者均保留正式文档。
差异页按「结果摘要 / 版本信息 / 内容差异」排列，支持仅看变更；无差异时顶部提示，正文默认折叠。窄面板按版本上下排列，保留源码行格式与横向滚动。
同步面板使用与日志页一致的「快捷同步 / 自定义同步 / 同步历史」页签，移除原有的「同步文档」标题栏。
快捷同步输入时匹配当前工作区的本地功能分支，必须从候选列表选中后才能开始；
支持方向键、Enter 选择和 Escape 关闭，修改文本后需重新选择。
可同步的分支遵循命名格式（`feature/开发者/YYYY-MM-DD-需求标题`），复用目录创建接口，
首先校验分支属于当前工作区仓库，拒绝借用父目录仓库；目录存在时直接使用。
与本地 `main`（不存在时使用 `master`）比较，两者均不存在则停止，不切换或创建 Git 分支，
不纳入未提交改动，不改动暂存区及源码文件，仅创建需求目录和生成文档。
随后复用现有提交选择及分阶段同步流程，不选择会话，先同步需求文档，
Host 持有同一个执行名额，成功或确认已同步后再同步技术方案。前端仅提交一次请求并观察状态，
切换页面、关闭面板或连接中断不影响 Host 继续执行。失败、取消、删除或插件卸载会阻止后续阶段。
两份文档保存同一个快捷同步 ID；连接中断后可按此 ID 观察整个流程，而非只观察需求文档。
Host 重启不自动恢复执行；任务状态从文档记录重建，中断后可从同步历史重试未完成文档。
自定义同步保留文档类型、提交、知识上下文及会话选择。切换页签保留当前进度。
显式选择提交时，列表与执行使用同一基准分支版本校验范围，并按每个所选提交相对其第一父提交的差异分析；不要求分支具有唯一共同祖先，也不纳入未选中的提交。显式空清单保持为空。未显式选择提交的自动范围同步仍要求唯一共同祖先。分支或基准版本变化时继续要求刷新提交列表。

准备、会话读取、代码分析、讨论分析、编辑及发布前均可停止任务。取消会传递到 Git、
会话来源和子代理；任务显示正在停止，等待实际资源清理后记录为已停止，不启动后续节点。
代码与会话分析独立并行，分块及汇总共用全局子代理并发名额，与知识库整理和其他委派任务共享上限。

失败或主动停止的任务，可从同步历史的「从未完成节点重试」或详情中的失败步骤、分块重试。
重试创建新执行记录，保留原记录；已完成并校验的分块、汇总、编辑和校验产物按节点复用，
只执行未完成节点，成功后继续剩余流程。已冻结的代码、会话、参考资料及文档基线继续使用，
发布前仍检查正式文档版本。输入或执行契约变化时明确拒绝复用；旧版本没有保存检查点的节点
需要重新执行。修改提示词、输出上限等执行规则后，旧记录可能不再兼容，应重新发起同步；
界面保留原记录并展示具体原因，未知错误码保留原始诊断，不中断面板渲染。
准备阶段尚未完成输入冻结时，重试重新准备来源。

ReqHub 侧栏依附当前会话。全局页面或尚未打开会话时，点击入口提示先打开会话，
不会调用未挂载的侧栏；会话界面挂载后再点击即可打开。

需求文档和技术方案的自定义同步设置共用「同步目标 / 代码范围 / 参考资料 / 会话来源」

显示。会话来源默认收起并显示已选数量，展开后通过 DSH / Codex 标签切换，保留各自的
筛选和选择；来源对应的刷新、管理及预览操作继续保留。底部常驻选择汇总和开始按钮，
窄面板下字段与操作自动纵向排列；原有同步校验及执行流程不变。

技术方案同步的代码与会话分析支持需求基准参考。自定义同步可搜索当前需求目录及子目录内的
文件，选定一项才生效，清空可取消；未选时沿用原同步流程。快捷同步固定使用本轮成功发布的
`requirement.md` 内容快照，不受随后对需求原文的编辑影响；需求阶段已同步而跳过时使用当前
需求文档。快捷同步不接受自定义参考覆盖。PDF、Word、Excel 复用现有解析器，其他文件须为
可读取的 UTF-8 文本；不可解析或超出读取预算时明确失败。

参考正文完整冻结为必读 artifact，代码和会话分析都需完整读取。它限定业务范围，但不能充当
实现证据。技术方案仍沿用技术文档结构，描述职责、架构、接口、数据流、约束与失败处理，
不会改写为需求文档。需求与实现冲突或缺少实现证据时列为待确认事项。参考路径和内容版本
参与同步去重，参考发生变化时会重新分析，即使所选 Git 提交没有变化。

同步页的「参考知识库」仅提供名称搜索、勾选、清空及刷新。同步时沿用 Host 的受控检索，
按当前需求从所选知识库获取相关资料；不选则不增加知识参考。知识库补充背景、术语和已有
约定，不替代需求基准、代码或会话证据，也不修改知识库内容。「关联影响与一致性审阅」
已从同步设置和任务详情移除，不再单独提供。

同步中的 Codex 工作区按当前项目的文件夹路径自动匹配，不提供切换入口。会话读取、刷新和
同步提交均校验路径归属，历史绑定及客户端传入的其他 Codex 工作区 ID 不能改变匹配结果。
没有匹配会话时显示空态；匹配多个工作区时明确提示，不猜选，也不影响仅使用代码或 DSH 会话同步。
DSH 与 Codex 会话按最近更新时间倒序展示，无更新时间时使用创建时间。
来源标签显示当前工作区会话总数与已选数，筛选不改变统计。
不可选会话淡化显示，并标明「无完整轮次」「读取失败」或「未就绪」；可读取的内容仍支持预览。

快捷同步和自定义同步共用的分析阶段保留 Markdown 报告与 JSON 索引两个产物。
报告只写简短总览、跨项风险及知识来源版本，变更明细与未决事项集中保存在 JSON 中。
汇总阶段仍完整读取各分析报告与索引，原文和提交清单按需读取；编辑阶段读取候选正文，
避免再读一份相同原文。连续编辑复用工具返回的候选哈希，需要定位文本时再读候选。
分析和汇总阶段只开放读取及分析输出工具；编辑阶段只开放读取及局部编辑工具，
不提交 report 或 changes。编辑回执记录候选修改，未完成提醒按计划块检查编辑进度。
子代理数量、证据完整性、变更保留、精确编辑、版本及发布校验保持不变。

### 日报与每天 08:00 的目录简报

任务报告新增「日报」页签，按 `general.timeZone`（默认 Asia/Shanghai）查看前一天文件，也可选择其他日期。文件按工作区和现有 `YYYY-MM-DD-需求名` 目录归类，保留作者等父目录；无法确认需求归属的会话、普通文件及跨需求知识页面归入「公共资料」，不猜测关联。

收集覆盖用户直接写入 docs 的文件、手动／快捷／定时同步产物、同步导出的新增和增量会话文件、写作保存文件，以及知识库实际发布的新增／更新页面。同步和写作在本地提交后登记，会话在导出后登记；直接放入 docs 的文件默认每分钟扫描一次。收集独立于飞书开关。知识库只收集正式页面，不收集其内部 staging、索引和缓存。

每天 08:00 按「工作区 × 需求目录」为昨天的每个非空分组生成一份简报。DSH 关闭时不能执行任务；启动后补执行当前昨天，避免重放全部历史。首次启用只依据修改时间发现昨天和今天仍存在的当前文件，界面标注「首次发现」；没有保存过的历史内容无法从今天覆盖后的文件重建。更早历史文件不补录，之后的新增和修改继续收集。

日报只保存文件路径、来源、产出日期、大小和文件版本标识，不保存或复制原文件正文。登记和扫描只读取文件元数据，没有日报文件大小、数量或快照存储配额。每天生成时从原位置流式读取，内容仅在当前模型步骤的有界缓冲中存在；同一天同一文件的清单采用最后一条产出记录。若原文件后来修改，明确标注使用生成时可读的当前内容；删除或无法读取时保留清单并说明正文不可用，不从日报档案恢复历史正文。旧实现的正文 BLOB 列会从日报控制库移除，不触碰工作区源文件。

简报保存到 `docs/<需求目录>/daily-reports/YYYY-MM-DD.md`，公共资料保存到 `docs/daily-reports/YYYY-MM-DD.md`。日报产物可以作为新文件交给独立飞书分发流程，自身不参与下一轮日报，防止循环汇总。

飞书分发和日报登记是本地文件提交后的两个独立消费者：日报异步登记不阻塞飞书入队，飞书关闭、忙碌或失败也不会阻止日报登记。飞书的上传队列、预算、重试和状态完全由飞书服务管理；日报不在其内部串行执行。会话正式文件由独立的 ConversationFiles 本地导出服务保存，使用 `conversation-files.sqlite` 记录导出归属，随后分别通知日报与飞书；关闭飞书不影响本地导出。

简报沿用受控 Host 模型任务：从原文件分块读取，逐批摘要，再合并摘要。二进制或无法完整读取的文件明确只依据元信息；任何模型失败保留文件清单与上次简报。界面区分待生成、运行中、完成、待更新和失败，并支持重试。旧输入结果不能覆盖新输入，用户修改过的简报不能被自动覆盖。修改计划或卸载取消并等待真实任务结束，重启按已处理的文件版本避免重复生成。

高级配置 `dailyReports` 由 Cordis schema 校验，只有用户能修改。默认自动简报开启；`enabled=false` 只关闭生成，登记继续。`scanIntervalMs` 为 1000–60000 毫秒，默认 60000。`maxBriefInputBytes` 默认 1 MB，限定单个模型步骤的完整输入（含元数据），不限制收集清单或整组文件总量；`maxModelCalls` 默认 32 个模型步骤（含合并摘要）。模型实际上下文容量还由 Host 校验。模型预算用尽时仅简报失败，不丢弃清单、不删除文件，也不影响飞书队列。分组和文件清单分别分页返回。

## Prompt 与输出语言

13 个内置任务模板使用英文，并遵循 `asd-ste100` 的清晰表达规则。模型的过程说明、进度、
同步分析报告、变更索引及任务完成回执使用英文。同步编辑阶段将英文建议转换成最终文档语言。
写作的 `overview` 使用英文，`content` 是最终文档；Wiki 页面、问答与检查结果属于
最终交付内容。知识库整理规则（用途、结构、语言）在「设置 → 知识库」中按工作区保存，供后续整理任务读取。

最终交付语言优先采用用户明确指定的语言，否则保留输入文档语言，再参考来源资料或问题语言；
无法判断时使用简体中文。原文引用、代码、路径、标识符和协议字段保留原样，不翻译无关正文。
统一语言约束在执行时加入，绑定、未绑定或无法加载 Skill 时均生效。已保存的自定义模板不会被
覆盖，执行时同样附加语言约束。语言约束依赖模型遵循，仍需在真实任务中检查输出。

## 界面语言（中英文切换）

「设置 → 通用 → 界面语言」保存 `general.uiLanguage`，三态：`follow`（默认，跟随宿主语言）、
`zh`、`en`。插件向宿主的 `reqHub` 命名空间注册 `zh` / `en` 两本字典；跟随模式下由宿主选择，
强制模式下绕过宿主译文直接取插件字典，因此界面语言与宿主语言可以不同。设置的加载、保存与卸载
复位与时区偏好共用同一套模块级外部 store，语言变化会让整个页签重新渲染。

界面文案全部收在 `src/client/locales/zh.js` 与 `en.js`（各 1950 个 key），共用 `t()` 输出；
契约测试锁定两本字典的 key 集合、插值变量名集合完全一致，且英文不得为空或残留中文。
`{name}` 插值在宿主译文分支与插件字典分支统一执行，未知 key 仍然抛错，强制语言字典缺 key 时
回退中文而不是让页面崩溃。

### 服务端稳定码协议

服务端**不再向 UI 输出自然语言文案**。所有用户可见字符串都是纯稳定码
（如 `WRITING_SESSION_DENIED`）或结构化描述符 `{ code, params }`；`src/server/messages.js`
的 `msg(code, params)` 构造描述符，无参数时返回纯码字符串，有参数时返回可抛出的 `Message`
（`Error` 子类，`JSON.stringify` 输出 `{code, params}`，字符串上下文退化为纯码）。
356 条稳定码的中文与英文译文作为 `server.*` 收在两本主字典里，纳入同一套 key 一致性契约。
`messageDescriptor()` 把描述符（含嵌套描述符、数组与 `Error` 对象）归一成可安全穿过
`postMessage` / 结构化克隆的普通对象，`messageFromDescriptor()` 在 worker 边界还原，
`describeError()` 供路由 `catch` 统一输出；`TaskExecutorError` 同时保留机器层 `.code`
与用户可见的 `.messageCode` / `.params`，避免动态数值（如超时毫秒数）在字符串上下文丢失。

客户端只有 `src/client/utils/serverMessage.js` 一个译码入口：`localizeMessage()` 按
`server.*` 及既有的 `sync.error.*` / `kb.error.*` / `writing.error.*` / `lark.*` /
`reports.reason.*` 命名空间查字典，递归翻译嵌套在 `params` 里的码与数组，未知码原样降级；
同模块的 `messageCode()` 在需要比较原始码的分支保留纯码，`clientError()` 把
`{code, params}` 响应包装成 `.message` 为纯码、`.params` 仍在的 `Error`，避免
`new Error(descriptor)` 变成 `[object Object]`。
接入点覆盖 `showToast`（通知单一入口）、日志面板、检查面板、同步历史、任务报告、Prompt 管理、
同步阶段与各处错误状态渲染。用户内容、路径、代码与协议字段始终原样保留，不会被改写。

服务端源码里剩余的中文只有 14 个中文分词停用词、2 个文档类型推断关键字，以及 4 处
内容质量判定与分支名校验用的中文正则——它们是检索/分类/校验数据而不是文案，不参与语言切换。

相互独立：英文界面仍可产出中文交付物。固定模板集中在 `src/server/content-templates.js`，

## 知识库（Knowledge V2）

知识库按工作区隔离，顶部页签为「Wiki / 资料 / 问答 / 检查」，右上角任务抽屉查看后台整理任务。
「Wiki」浏览最近一次发布的知识页面，按聚合、实体、概念、主题、来源等分组；「资料」查看已入库的
文档与会话、手动导入与排除；「问答」基于冻结证据提问并给出引用；「检查」展示结构与引用问题。
知识库设置位于「设置 → 知识库」，按「自动整理与每日更新」「整理规则」「清空知识库」分区保存；
整理规则（用途、结构、语言）按工作区保存，保存后排队一次整理任务应用到后续运行。

「资料」的「导入文件」由 Host 按当前工作区已授权的文档根目录递归枚举白名单文本文件，
不需要用户填写路径；弹窗顶部只显示当前搜索的基础路径（工作区名与授权文档根目录的绝对路径）。
列表逐项标注未导入、已导入、有更新、超过大小限制或无法读取；路径搜索输入后需点击「搜索」
或按 Enter 才生效，状态筛选即时生效，汇总的文件总数与可导入数按两者共同筛选后的结果计算。
支持全选当前可导入项与清空选择；已导入且内容未变的文件不可勾选，
导入时仍按原路径重新校验边界、大小与内容，逐项返回保存 / 跳过 / 失败结果；一次最多导入
`LIMITS.batchFiles` 个文件，超出时明确提示而不静默截断。候选枚举上限为 `LIMITS.candidateFiles`，
达到上限时返回截断标记并在界面提示；目录符号链接和隐藏目录会被跳过。这是打开弹窗时的按需枚举，
不是目录监听，文件变化需要重新打开弹窗或刷新。弹窗按共用 `ActionBar` 划分筛选工具区、文件列表
卡片与底部操作区，工具栏控件统一 `sm` 尺寸，卡片内的分页控制与文件行共用左右边界。

「资料」的「导入会话」按 DSH / Codex 分页签，同一时刻只显示一个来源；两个页签常驻挂载，
切换时各自的搜索草稿与选择不丢失，已选轮次跨页签汇总。每个页签内包含该来源的紧凑拉取会话卡片（只保留读取状态与刷新入口）、
标题搜索、会话列表与分页，会话行沿用同步功能的卡片式选中态（标题、入库状态徽标、轮次与快照摘要、
「选择轮次」行内操作），列表与分页共用卡片内边界。Tab 栏右侧显示当前工作区与项目路径，
底部用共用 `ActionBar` 承载导入模式、保存并更新 Wiki、选择汇总与关闭 / 导入按钮；
工具栏与列表行控件统一 `sm` 尺寸。轮次在独立弹窗中按快照版本逐轮勾选，切换版本会清空该会话选择。
「查看内容」在同一冻结快照里只读展开逐轮原始对话：服务端规范化消息（兼容只有 `userInput` /
`summary` 的旧快照）；若运行中的 Host 仍是旧版本、未返回正文，前端按需读取同步功能的
`/req-hub/session-turns` 补齐并标注来源；确实取不到正文时给出明确提示，而不是渲染空白轮次。

「设置 → 知识库」的自动整理配置仅包含 `knowledgeV2` 下的六个字段：

- `autoManage`（默认关闭）：文档保存后是否自动按工作区防抖导入；
- `autoManageDelayMs`（默认 30000，范围 0–3600000）：同一工作区连续保存的静默等待，0 表示立即执行；
- `dailyUpdateEnabled`（默认关闭）：是否启用每日后台同步；
- `dailyUpdateTime`（默认 `02:00`，24 小时制 `HH:mm`）：每日执行时间；
- `dailyImportConversations`（默认关闭）：每日同步时是否按工作区实际路径重新发现并导入未归档会话；
- `larkPushEnabled`（默认关闭）：每日更新的最终产物是否推送飞书。

两个模块各有独立的「推送飞书」开关：同步计划页使用 `sync.larkPushEnabled`，知识库设置页使用
`knowledgeV2.larkPushEnabled`，默认均关闭，只作用于定时任务（不影响手动同步与文件预览页的按钮）。
开启后，同步模块把该分支生成的 `requirement.md` / `design.md` 推送到
`<绑定父位置>/<docsDir>/<需求目录>/`；知识库模块等待本轮整理编译结束后，把当前发布代
`releases/{generationId}/wiki/*.md` 推送到 `<绑定父位置>/<docsDir>/knowledge-v2/`。
两者都复用文件预览页同一套飞书发布器：先逐层检查同名目录、缺失才创建，再按同名文件决定
`markdown +overwrite` 或 `markdown +create`；一次批量共享身份校验与目录查询，避免重复远端调用。
推送结果按文件写入任务报告（含新建/更新动作、远端地址、跳过原因或错误码），推送失败只记为
独立报告项，不把已成功的文档同步或知识库整理改成失败。工作区未绑定飞书目标、CLI 未验证或
当前没有产物时记为「跳过」并给出原因；需要有效的 `larkTargets` 绑定与已验证的 CLI 身份。

时区复用「通用」中的 `general.timeZone`，不再单独设置。文档保存触发的防抖定时器以工作区为键，
连续保存只重置该工作区的等待时间；每日同步由 Host 在后台按已注册工作区逐个执行，同一工作区
同一天只触发一次，彼此独立，不依赖当前打开的页面或 Agent 会话，也不继承其他工作区的会话历史。
关闭开关、修改时间或卸载插件会取消排队并等待已启动任务结束。

入库文档与会话进入按工作区串行的整理队列，产出新的知识页面后直接发布为新一轮 Wiki；问答与
检查始终对最近一次发布生效，不再设人工审批、待审阅或回退流程。整理任务的进度、失败与产物
在任务抽屉和侧边栏「任务报告 → 知识库」中按工作区分组查看，旧回调不能把中断报告改回成功。

「设置 → 通用 → 高级 → 子代理并发数」控制 ReqHub 的所有 subagent 调用，配置字段为
`ai.delegation.maxConcurrency`，默认 3，范围 1–16。同步分块、知识库每日整理、文档编写和
语义知识增强共用同一 FIFO 队列，跨工作区和父会话共享额度；其他宿主插件的子代理不在此预算内。
满额后保留排队状态，等待期间可以取消；等待不消耗子代理执行超时。创建失败、执行失败或取消后，
额度须等启动过程及子代理清理真正结束才释放。卸载会停止准入、取消排队及活动任务，并等待清理。
保存新的上限后立即用于共享队列；降低上限不会强行打断已运行的任务，会在额度自然释放后限流。

「设置 → 通用」可设置 `defaultUsername`，用于新建功能默认填充和定时分支匹配。
同步计划页只编辑定时快捷同步参数，默认用户名和时区引用通用设置；标题后的帮助图标在悬停或键盘聚焦时显示说明，
同步日期的说明中提供分支匹配规则及示例。关闭开关时保留并禁用执行参数，点击保存后生效。
定时快捷同步默认关闭，使用 `sync.dailyUpdateEnabled`、`dailyUpdateTime`、
`dailyOffsetDays`，时区使用 `general.timeZone`。T-1 表示前一个日历日，例如北京时间 11 月 4 日运行，
匹配 `feature/alice/2026-11-03-*`；用户名留空匹配 `feature/2026-11-03-*`。x 支持 0–365 天。
按当前已注册工作区和匹配的本地分支依次处理，复用「快捷同步」的需求文档、技术方案顺序和
发布校验，不切换分支，不自动拉取远端引用；缺少需求目录时在配置的文档根目录内创建。
自动任务与手动同步共享执行所有权，遇到手动同步会等待；关闭计划、修改计划或卸载会取消并
等待当前批次。失败保留已有产物，继续其余分支。定时任务为每个分支创建独立的后台委托会话，
路由直接使用该后台 agent，不再从宿主活跃会话注册表反查，因此没有打开会话的工作区同样会执行；
只有真的无法创建后台会话时才记为失败，并在任务报告中查看原因。新启用或修改计划时不补跑已错过的时间；
同一配置存储、同一天最多触发一次，宿主运行时检查到期，重启不追补历史日期。非 Git 目录、
已移除的检出目录或不是仓库根的工作区记为「跳过」并写明原因，不再让整个批次变成部分失败。
被取消或因进程中断而停在 `interrupted` / `cancelled` 的当天报告会在下一次检查时续跑，
已完成项保留，未完成项重新处理。

插件侧边栏「日志」上方为「任务报告」。知识库 / 同步两页按日期倒序展示每日批次和统计，
详情按工作区分组。知识库列出每份文档和会话的实际处理状态，会话带 DSH / Codex 标签，
可跳转到知识来源详情和原文；失败、完成与等待分别展示。
同步列出每个分支的处理结果、需求文档和技术方案记录，可打开对应同步历史或跳转查看产物。
报告按当前配置存储隔离，仅显示仍有效的工作区。取消或进程中断会保留已完成项并停止未完成项，
当天报告可在下一个检查周期续跑；旧回调不能把中断报告改回成功。推送飞书的记录与跳过原因
同样按工作区分组展示。

开启 `dailyImportConversations` 后，每日计划仅将来源工作区及会话 `cwd` 的实际路径与目标工作区
一致的未归档主会话导入对应知识库，再排队整理。路径解析会处理符号链接、junction 和 Windows
大小写；嵌套或其他工作区不会混入当前知识库。无需预先手动拉取，也不改变手动选择；来源工作区、
项目、路径和版本保留在知识条目中。会话内容复用手工拉取、预览与导入的解析和渲染逻辑，保留用户
输入、补充输入、助手中间回复、最终回复（总结）及轮次顺序；过滤工具调用、工具结果、隐藏思考和
注入上下文，不另做摘要替代原文。重复轮次跳过，新增或变化轮次更新同一知识条目，保留来源、版本和
轮次状态；未完成轮次仍标注为未完成，不能当作确认结论。按会话分批导入，超预算明确记为失败，
不截断正文。单个来源或会话失败时继续处理其余内容，并维护已成功导入的资料；失败计数、原因和
导入统计保存在任务报告与任务抽屉中，下一日重试失败会话。关闭计划、重新配置或卸载会取消并等待
拉取流程，已提交的知识条目保留。

调度由正在运行的 DSH 宿主持有，按分钟检查；只要当天已过配置的执行时间就会补跑，避免宿主繁忙
或重启恰好错过那一分钟导致整天不执行。同一配置存储、同一天最多触发一次，标记持久化在
`task-reports.sqlite` 的每日报告中，重启不会重复执行；重复导入按内容哈希跳过，没有待更新资料时
不创建整理任务。每日同步先按已入库文件重扫并保存变更，再按需导入会话，最后统一排队一次整理，
并在有界等待编译完成后推送飞书（开关开启时）。会话库不可用、某工作区会话枚举失败或单个会话
读取失败，都只记为部分失败并继续其余工作区，不阻断该工作区的文件同步与 Wiki 编译；页面当前
显示哪个工作区、是否有活跃会话都不参与后台同步，所有已注册工作区一律按各自路径独立处理。
旧格式会话快照（只有 `userInput` / `summary`）会先规范化再判断是否有可导入轮次，不会因缺少
`messages` 抛错而中断整批。关闭计划、修改配置或卸载会取消排队并等待已启动任务结束。

存储上，知识库本身只使用 `knowledge-v2/` 下的普通文件（原始快照、发布代、规则与任务清单），
不读取、不迁移也不保留旧知识库数据。会话库、知识增强库和 `task-reports.sqlite` 仍使用
`node:sqlite`，分别服务于会话管理、知识增强与任务报告，与知识库内容存储无关。运行详情以
任务抽屉和任务报告为准，不单独保留旧版「运行事件」页面。

## 新建功能

点击侧边栏「新建」按钮或按 `Ctrl+N` 打开新建面板。系统会读取当前 Git 分支名，自动填充表单字段。

### 场景一：手动新建需求目录

当前分支名符合 `feature/<开发者>/<日期>-<标题>` 格式时，表单自动填充开发者、日期和标题。可选勾选「同时新建 Git 分支」从当前 HEAD 创建新分支。

**浅色主题 - 宽屏 (900px)**：

![新建表单 - 浅色宽屏](docs/create-form-light-wide.png)

**浅色主题 - 窄屏 (400px)**：

![新建表单 - 浅色窄屏](docs/create-form-light-narrow.png)

**深色主题 - 宽屏 (900px)**：

![新建表单 - 深色宽屏](docs/create-form-dark-wide.png)

**深色主题 - 窄屏 (400px)**：

![新建表单 - 深色窄屏](docs/create-form-dark-narrow.png)

**涉及功能**：

- 状态预检（`/create-status`）— 读取 Git 分支、HEAD、未提交修改和中间状态
- 分支名自动填充 — 解析 `feature/<开发者>/<日期>-<标题>` 格式
- 可选新建 Git 分支 — 从当前 HEAD 创建并切换
- 预览路径 — 实时显示将创建的目录和分支名
- 确认对话框 — 勾选新建分支时弹出确认
- 创建后自动选中 — 刷新目录树并选中新建的需求

### 场景二：在 main/master 分支新建

当前处于 main/master 分支且无未提交修改时，表单顶部额外显示「拉取并合并远端」按钮，可先更新主分支再新建。

**涉及功能**：

- 更新主分支（`/update-main`）— 校验 HEAD → 查找远端 → fetch → fast-forward merge
- 冲突处理 — 分支或文件已变化、无远端、拉取失败、无法快进分别报错
- 更新后刷新 — 成功后重新检查状态，继续新建操作

### 场景三：定位会话需求（分支名不规范）

点击顶栏「定位」按钮，系统根据当前 DSH 会话的工作目录自动定位工作区。如果分支名不符合规范，跳转到新建表单并提示用户。
跨工作区定位先解析分支和需求目录，再一次性切换工作区并恢复定位结果；不依赖延时或二次点击。目录不存在时保留创建确认，旧请求取消后不能覆盖新定位。

**涉及功能**：

- 获取当前 DSH 会话 — 从 `window.__DSH_CTX__` 读取会话 ID
- 匹配工作区 — 按完整路径匹配已注册工作区
- 分支名解析 — 支持多种格式（`feature/<开发者>/<日期>-<标题>` 等）
- 不符合规范时跳转 — 清空选择，打开新建表单，勾选「新建分支」
- 符合规范但目录不存在 — 弹出确认对话框，确认后创建目录

### 场景四：浏览已有需求目录

点击顶栏「选择需求」按钮，弹出需求目录浏览窗口，按开发者分组显示所有需求。

- 树形展示 — 开发者节点可展开/折叠，显示需求数量
- 需求项展示 — 显示日期、标题、文件数

- 切换后清空选择 — 清空开发者和需求选择，保存配置
- 重新检查创建状态 — 切换后重新拉取 `/create-status`

### 场景六：已有需求拦截

如果当前分支名已匹配一个存在的需求目录，点击「新建」时弹出「当前需求已创建」通知，显示分支名和目录路径，不打开表单。

**涉及功能**：

- 已有需求检测 — 在 `/create-status` 中检查分支名是否匹配已存在目录
- 拦截通知 — 弹出对话框显示分支名和目录路径
- 提示更换工作区 — 如需新建其他需求，需先切换工作区
