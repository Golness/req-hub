# ReqHub — 需求中心

> DeepSeek Harness 插件：需求文档管理、知识库与写作、文档同步、关联审阅

## 1. 插件定位

ReqHub 是面向 **DeepSeek Harness（DSH）** 的需求管理插件，解决以下核心问题：

- **需求文档散落** — 需求文档、技术方案、CR 记录分散在代码仓库中，缺乏统一管理
- **代码与文档脱节** — 代码变更后，需求文档没有同步更新，导致文档过期
- **需求追溯困难** — 无法快速定位某个功能点对应的需求文档和代码变更
- **知识复用困难** — 文档与会话缺少统一的来源、版本及可审阅关联依据

ReqHub 将需求文档组织为 **开发者 → 需求 → 文件** 三级目录结构，支持代码变更同步到文档，并从选中文件构建工作区知识库，以全文检索查找知识与来源。

---

## 2. 功能概览

### 2.1 需求目录管理

- **三级目录树**：开发者 → 需求（日期-标题）→ 文档文件
- **Git 分支自动解析**：从 `feature/<开发者>/<日期>-<标题>` 格式分支名自动创建需求目录
- **多工作区支持**：切换不同 DSH 工作区，每个工作区独立管理需求文档
- **文件预览**：支持 Markdown、HTML、TXT 文件预览，含 Mermaid 图表和代码高亮

### 2.2 工作区知识库

- **四个标签页**：侧边栏统一进入“知识库”，依次提供“查看文档”“文档入库”“会话入库”“搜索”。关联与检查进入文档查看、写作、同步和搜索详情的上下文中；GitNexus 管理位于设置。查看文档保留文件树、筛选、排序、拖宽、预览、原文编辑、保存和目录；切换知识库标签页保留已打开文档的草稿。
- **单篇入库**：未入库文档的面包屑旁显示“入库”，使用文档实际所属工作区和完整路径提交；已入库文档显示状态，文件变化后可更新入库。文档未保存时先保存，再入库。
- **分开入库**：“文档入库”保留文件多选、任务进度、取消和重试；“会话入库”直接使用插件当前工作区，按完整路径匹配 DSH/Codex 来源，入库到当前工作区知识库，无需再选择来源或目标工作区。两个来源保留刷新进度、会话多选、轮次选择和重复导入合并。Windows 路径统一大小写与分隔符，同名但不同路径不会混入；没有匹配的 Codex 工作区时显示空态。
- **跨需求多选**：点击文件行预览，复选框选择文件；切换需求目录保留选择，切换工作区清空选择。目录勾选只作用于当前筛选结果，隐藏选择保留。
- **显式分析**：在右侧点击“分析（N）”，本地解析选中文件并将完整正文入库。无需模型、子代理或活跃会话。仅处理选中文件，支持 MD/TXT/TEXT/HTML/HTM/JSON、文字型 PDF、Word（.docx）和 Excel（.xlsx）。每次最多 200 个文件；文本文件最多 2 MiB，PDF/Office 最多 20 MiB。PDF 最多 500 页，Excel 最多 50 个工作表、10 万个非空单元格，Word 最多 1 万个段落或表格行，提取正文最多 200 万字符。Office 解压内容最多 40 MiB、1 万项，解析超过 30 秒会终止并提示拆分文件。
- **文档解析**：采用本地 PDF.js、Mammoth、ExcelJS，在独立 Worker 中解析，无需 LLM。保留 PDF 页码、Word 提取段落、Excel 工作表与单元格位置；搜索结果显示命中位置，来源预览显示只读提取文本。Excel 保留公式和已有缓存结果，不计算公式、不执行宏、不访问外部链接。扫描型 PDF、加密文件、旧 `.doc` / `.xls` 不支持；混合 PDF 中无文字页会提示，不执行 OCR。源文件仅以只读方式打开，保持原样。
- **增量与恢复**：已成功且内容/分析配置未变的文件跳过；支持取消、部分失败重试、刷新恢复进度，重启后的未完成任务标记为中断。已发布的成功文件保留。
- **文档与版本**：按文件路径分别保存完整正文、来源和版本；同名文件及内容差异独立保留，更新时替换该文件全文并同步更新索引。
- **存储**：所有工作区共用 `<DSH_HOME>/req-hub/knowledge/knowledge.sqlite`（未设置 DSH_HOME 时为 `~/.dsh/req-hub/knowledge/knowledge.sqlite`），采用 SQLite FTS5；同目录 `documents/` 保存带来源元数据的 Markdown 正文副本。数据库是内容、版本与任务的权威来源，Markdown 副本可在启动时恢复，不直接编辑回写源文件。旧工作区数据库直接删除，不迁移、不适配，源文件不删除。需要 Node.js ^22.19.0 或 >=24.0.0，并支持 `node:sqlite` 和 FTS5。
- **参考移植**：存储、检索与版本设计来自 dsh-knowledge 2.15.4，保留 [MIT 许可与来源说明](src/server/knowledge/NOTICE.md)。知识库数据已从 Git 默认跟踪范围排除。

### 2.3 文档同步

同步状态由 `src/shared/sync-task.cjs` 和服务端 `SyncLifecycle` 统一管理。整体任务为 `running → completed / failed`，取消为 `running → cancelling → aborted`；所有终态都有结束时间，后续事件不能将其改回运行中。步骤和分块分别收敛：失败步骤保留错误，未执行步骤跳过；取消时未结束步骤和分块标记终止。每次更新先持久化，再推送完整任务快照；SSE 断线后按任务 ID 查询权威状态。

文档发布状态与整体任务状态分开保存。附加分析失败会使整体任务失败，但已发布文档仍作为后续同步基准和可对比版本，不会因此重复应用补丁。旧同步记录中遗留的运行态、未结束步骤会在读取时校正。重启时核验发布日志、快照和正式文件哈希，避免误报成功。插件卸载会取消任务并等待 one-shot 子代理释放资源后再移除受控工具。

- **基准分支**：默认检查本地 `main`，不存在则使用 `master`，均不存在时提示手动填写。
- **Commit 多选**：列出目标分支相对基准分支独有的提交，默认全选，支持筛选、勾选、全选/清空；实际同步使用所选提交的差异。分支更新后需刷新列表。未提交改动可单独选择是否包含。

- **分阶段同步**：代码差异分析 → 会话提取 → 讨论差异分析 → 增量合并 → 保存文件
- **Git 代码差异**：自动分析分支与基准分支的代码变更
- **DSH 会话集成**：选择列表展示总轮次和可同步轮次；完整预览按顺序标注用户输入、补充输入、助手中间回复及最终回复。仅正常完成且有用户输入和有效最终回复的轮次参与同步，排除思考、工具、系统提示和注入上下文。
- **会话快照与文件引用**：预览和同步校验同一份正文快照版本，会话变化后需刷新重选；本次同步目录的 `input/sessions/` 保存每会话及分轮 Markdown，Subagent 通过受控文件引用读取，复用代码同步的哈希核验、读取覆盖检查和完整输入预算。优先按会话、完整轮次分块；单轮超限时按消息边界拆分，单条消息过长再按连续文本片段拆分，保留来源、轮次及位置，完整性由程序校验。同步去重同时考虑所选会话快照。
- **同步预算**：按子代理模型的上下文容量、输出额度和 DSH 自动压缩阈值计算输入预算，并留出余量；模型未提供容量时回退到 150,000 的估算 token 预算。中英文、代码及 JSON 封装统一按文本估算，不再把 UTF-8 字节数视为 token 数。必读 diff 与会话证据参与分块，完整冻结源码按独立额度按需读取；运行时复核实际路由与宿主 TokenMeter。工具返回按序列化后的长度分页，防止 DSH 裁剪结果；如证据已被宿主压缩或裁剪，停止本次分析，不继续发布。
- **增量合并**：AI 将代码变更智能合并到现有文档，而非覆盖
- **Codex 会话集成**：在 DSH 会话区域下点击“选择 Codex 工作区”，按项目名称与路径搜索并选择，拉取该工作区的未归档主会话。支持多根工作区及项目关联的 worktree，会话列表、内容预览和多选方式与 DSH 一致；可与 DSH 会话混合加入同一次讨论分析。刷新会话会重新读取内容并清空旧勾选；只分析完整轮次，未完成轮次保留在预览中。
- **Codex 读取**：移植 [dsh-codex-migrate](https://github.com/polarskicpl/dsh-codex-migrate) 的 JSONL 文本读取能力（[MIT 来源说明](src/server/codex-sessions/NOTICE.md)）。只读 `CODEX_HOME`（默认 `~/.codex`）的项目、会话及归档元数据，无 SQLite 时读取活跃 JSONL 和标题索引。用户输入、补充输入、中间回复和最终回复保留原顺序，去除镜像重复；不导入系统上下文、隐藏推理和工具结果。不修改 Codex，不创建 DSH 会话。
- **统一会话库**：DSH 与 Codex 共用 `<DSH 全局目录>/req-hub/conversations/conversations.sqlite`，优先使用宿主 `profileContext.home`，独立运行回退 `DSH_HOME` 或 `~/.dsh`。按来源实例、来源工作区区分内容，按当前 DSH profile 保存工作区绑定。SQLite 按来源工作区共享轮次正文，版本仅保存有序轮次引用；每个会话只保留一份可重建的 `documents/<scope>/<conversation>/current.md`，历史预览直接从数据库重建。
- **会话管理**：同步页“管理会话”可搜索、按来源筛选、查看版本及任务引用数量、删除本地副本或未引用的旧版本、查看刷新任务进度及取消。首次选择 DSH 会话工作区自动入库，后续显式刷新；Codex 保留选择工作区及流式刷新进度。列表、预览与同步分析共用版本；来源改变、归档或不可读时不能静默使用旧内容。同步任务锁定所用版本，删除任务后解除引用，任务自己的冻结证据继续保留。
- **会话库回收与升级**：旧版会话库正文、快照、绑定、引用、刷新记录及 Markdown 投影在首次打开时全部移除，不迁移；DSH / Codex 源会话、知识库已入库正文、正式文档与同步任务的独立冻结证据保持不变。重新选择来源工作区并刷新即可重新拉取。当前格式重启不会再次清空。
- **会话库保留策略**：默认保留最近 3 个版本，7 天以前的非当前、无引用版本可回收，1 小时宽限期保护刚选择的版本；被同步任务引用的版本和当前版本始终保留。来源消失或不可用 30 天后，未被引用的本地副本可清理。刷新记录最多保留 100 条、7 天，运行中任务不清理；工作区访问关系独立于刷新记录。启动、刷新、管理列表和解除同步引用时执行清理，后台每 15 分钟检查；“管理会话”显示正文与 Markdown 占用、版本和引用数量，并提供清理入口。容量按授权来源工作区统计，不将共享 SQLite 文件伪装成单个工作区的物理占用。
- **会话库配置**：Cordis Config 的 `conversations` 支持 `retainedVersions`（默认 3，至少 1）、`versionRetentionDays`（7）、`missingRetentionDays`（30，可设 0）、`jobRetentionDays`（7）、`retainedJobs`（100）和 `graceHours`（1，可设 0）。最近版本与引用保护优先于清理目标；新增会话、轮次和有引用的历史仍会占用相应空间。
- **会话库改造验证（2026-10-25）**：Client / Server 共 61 个测试文件、477 项测试通过，覆盖 DSH / Codex 拉取、来源隔离、预览与轮次选择、知识库导入、同步证据、版本去重与回收、引用保护、旧库清理、取消和卸载；UI 约束、构建、发布包加载与 `git diff --check` 通过。旧库清理使用独立临时数据验证，实际数据由升级后的插件首次打开时清理；未执行真实宿主视觉或真实模型端到端验收。
- **会话导入知识库**：知识库和“管理会话”均提供“导入会话到知识库”，固定使用当前插件工作区。仅显示当前 profile 已拉取、来源实例仍匹配且路径属于当前工作区的会话副本，Codex 以每个会话的 cwd 与当前工作区完整路径一致为准，不以项目名或多根项目分组代替归属校验；列表、刷新结果、轮次预览与入库均检查范围。按左右两列展示（DSH 在左、Codex 在右），支持标题搜索、多会话、多轮次及指定快照版本。轮次在对应会话下展开、收起，不预留右侧详情栏；收起保留勾选，切换版本后清空该会话勾选，避免混用版本。
- **共用会话同步入口**：知识库页面直接刷新当前工作区的 DSH 或 Codex 会话，与文档同步页复用来源组件、进度协议和会话库服务，无需先启动文档同步任务。知识库入口不提供工作区选择，Codex 刷新由服务端按当前工作区路径重新匹配，不沿用指向其他路径的旧绑定。拉取后自动更新可导入会话，刷新时清空旧轮次勾选。
- **重复导入规则**：按“目标知识库作用域 + 来源会话身份”保持一个知识条目；所选轮次与既有轮次取并集，相同轮次正文不变则跳过，已变化且本次选中的轮次才更新，未选中的已导入内容保留。不同会话、来源实例或目标知识库互不去重。优先使用原生轮次 ID；旧导出无原生 ID 时使用带输入校验的轮次序号，无法可靠匹配时拒绝自动覆盖。每次最多 100 个会话、1000 轮，所选输入和本次生成内容分别限制为 16 MiB，超限整批失败，不截断。并发请求串行合并，异常整批回滚，重复提交不新增重复版本。
- **知识中的会话**：保存独立的所选原文、用户输入、中间及最终回复，保留来源提供者、来源工作区及路径、原生会话标识、轮次、快照哈希和正文行号。未完成轮次允许显式导入并标记为记录，不能当作已确认结论。知识库列表和全局搜索显示会话来源，详情可追溯各轮版本，搜索结果按轮次定位；历史知识版本保留各自来源。来源会话更新不会自动覆盖知识，删除会话库副本不影响知识。条目参与现有 SQLite FTS 检索及所选知识库的写作检索、完整读取、引用校验，模型只能读取实际导入的轮次。导入内容属于虚拟会话来源，不会被当成缺失的工作区文件，亦不会尝试打开不存在的源文件路径。
- **旧会话数据移除**：不迁移、不双读、不兼容旧会话存储。插件首次处理同步相关请求时删除旧 `req-hub/codex/`；扫描当前注册工作区的配置文档目录，删除旧任务 `input/sessions/` 并清理相应列表引用，已生成文档、其他任务产物和知识库保留。之后载入旧任务状态时也会清理。源 DSH/Codex 会话始终只读；链接越界或损坏状态会明确报错，避免扩大删除范围。
- **同步历史**：记录每次同步的完整过程和结果，支持回溯查看
- **发布即结束**：同步完成文档校验与发布后直接结束，不再执行额外 AI 元数据分析。
- **后台任务与通知**：离开同步页面或关闭 ReqHub 标签页不会取消服务端任务；底部栏独立显示文档类型、需求、当前步骤和分块进度，结束后保留成功、失败或终止提示，可点击查看详情。需求文档与技术方案在整个 ReqHub 中共用一个执行名额，服务端阻止跨页面、跨工作区并发启动。
- **异常任务兜底**：执行权由服务端监管，不以页面在线或定时查询作为存活依据。无执行者的残留任务自动归档；准备阶段 5 分钟无进展、执行阶段 25 分钟无进展、取消收尾超过 30 秒或总执行超过 6 小时会触发取消、封闭工具权限并回收名额。每次尝试用独立快照目录隔离，迟到事件不得更新或结束新的同 ID 任务；服务重启仍按已有发布日志和文档哈希核验恢复。
- **手动删除任务**：进度页、同步历史和底部栏均可直接删除任务，包括运行中、终止中和准备中的任务。删除会尝试终止并撤销执行权限，立即释放名额，不等待子代理收尾，不弹出终止失败提示；移除任务记录、通知、快照与中间文件，保留正式 `requirement.md`、`design.md`、源文件及所选原始会话。旧回调不能恢复已删除任务，也不能删除重试产生的新目录。

### 2.4 搜索

- **知识库搜索**：点击知识库第四个标签页“搜索”或 Ctrl/Cmd+K，搜索整个知识库，覆盖统一数据库中所有已入库文档，不受当前工作区限制。
- **本地全文检索**：FTS5 候选、中文关键词补召回和相关性排序；无需活跃会话或模型调用。直接查询同一数据库，所有文档统一排序，显示更多时最多 100 条，达到上限可收窄查询。部分工作区不可用时保留其他结果并提示检索不完整。
- **知识与来源**：结果标明所属工作区，详情、版本及原文件按来源工作区读取；来源被修改会标注过期，已删除或不可读的唯一来源不会继续参与搜索。

更新插件源码后请重新加载/重启对应 DSH 插件进程，使新增服务端知识库路由注册生效；`npm run build` 生成客户端产物。知识库可重建，备份时应连同 SQLite 数据库及其 WAL 一起处理，建议先停止插件再备份。

### 2.5 写作

- **两种文档**：需求文档、技术方案，可从模板或空白起稿
- **知识辅助优化**：多选工作区知识库，沿用 Subagent 调用链读取资料优化正文
- **差异审阅**：写作、检查建议、同步版本对比共用独立左右审阅页，总览与正文分开。写作逐项采用或保留原文，完成后一次合并；返回保留待审决定，原文变更时阻止直接覆盖。
- **任务反馈**：写作与文档检查显示准备、分析、资料读取、校验及取消状态和实际用时；无可靠百分比时不预估剩余时间。写作运行期间可继续编辑正文。
- **写作知识范围**：首次默认当前工作区对应知识库，此后按工作区记住用户选择（包括清空）；不会因刷新重置选择。

### 2.6 来源与版本追溯

- **知识库**：文档详情展示原文来源、位置及入库版本。
- **同步历史**：保留提交、所选会话、执行步骤、生成文件和文档版本对比。

### 2.7 其他功能

- **日志系统**：分类日志（级别 + 标签），实时查看和过滤
- **技能浏览**：查看 DSH 技能列表和内容预览
- **设置管理**：AI 配置、模型选择、Prompt 模板管理
- **文件树侧边栏**：可拖拽调整宽度的文件列表，支持按类型过滤和排序

同步运行数据统一位于 `<DSH_HOME>/req-hub/sync/`（未设置时使用 `~/.dsh`），SQLite 保存工作区、任务、执行、引用和租约；`workspaces/<workspaceKey>/objects/` 按 SHA-256 去重，`attempts/<attemptId>/` 保存报告与发布产物。每次重试都有独立历史；需求目录只保留正式文档。

升级后首次访问同步入口会移除注册工作区文档根目录内的旧 `sync-logs`，不迁移旧历史。正式文档、会话正文和知识库保持不变。清理拒绝越界路径与链接目录；旧同步持有的会话引用会解除。

同步历史提供容量统计、回收入口，以及“删除本次执行”和“删除整个任务”。无引用对象有一小时宽限期；每类文档最新发布版本受自动保留策略保护。Config 的 `sync.retentionDays`、`sync.retainedAttempts`、`sync.capacityBytes` 分别控制保留天数、执行数量和工作区容量目标，均默认 `0`（关闭）。策略在访问同步状态或执行清理时应用，运行与取消中的任务不自动删除。容量目标可能因受保护数据或宽限期暂时无法达到；统计不含全局共享 SQLite 数据库文件。

**Git 分支命名规范**：
- `feature/<开发者>/<日期>-<标题>` → 自动解析为需求目录
- 支持 `YYYY-MM-DD` 和 `YYYYMMDD` 两种日期格式

## 4. 使用流程

### 4.1 安装

1. 将插件放入 DSH 的插件目录
2. 确保 `cordis.patch.yml` 已配置：
   ```yaml
   - insert:
       - id: req-hub
         name: '@local/req-hub'
   ```
3. 构建客户端：
   ```bash
   pnpm install
   pnpm run build
   ```
4. 重启 DSH，在右侧边栏找到 "Req Hub" 按钮

### 4.2 初始化

1. **选择工作区**：点击顶部"工作区"下拉框，选择目标 DSH 工作区
2. **设置文档路径**：点击"项目路径"，配置需求文档根目录（默认 `docs`）
3. **创建需求目录**：
   - 确保 Git 分支名符合 `feature/<开发者>/<日期>-<标题>` 格式
   - 点击 Rail 栏"新建"按钮，自动解析分支名并创建目录
   - 或手动在 `docs/<开发者>/` 下创建 `YYYY-MM-DD-标题` 格式目录

### 4.3 日常使用

#### 查看和编辑文档

1. 在左侧目录树中选择需求
2. 点击 Rail 栏"查看"按钮，打开文件树侧边栏
3. 在文件树中点击文件，右侧面板显示预览
4. 支持 Markdown 渲染、Mermaid 图表、代码高亮

#### 来源与版本追溯

在知识库查看文档来源和版本记录；在同步面板的“同步历史”查看任务详情及文档版本差异。同步不再提供“同步后操作”，也不再生成 `.meta.json`。

#### 文档同步

1. 确保当前 Git 分支对应目标需求
2. 在左侧目录树中选择需求

4. 选择同步类型（需求文档 / 技术方案）
5. 系统自动执行分阶段同步：
   - **初始化**：检测代码变更
   - **会话提取**：提取相关 DSH 会话对话
   - **代码差异分析**：分析代码变更内容
   - **讨论差异分析**：分析会话中的讨论内容
   - **增量合并**：AI 将变更合并到文档
   - **保存文件**：写入更新后的文档

#### 搜索

1. 点击 Rail 栏“搜索”或按 Ctrl/Cmd+K
2. 输入关键词，检索全局知识库中已入库的文档
3. 点击结果查看命中内容、来源与版本

#### 写作

1. 点击 Rail 栏“写作”，选择需求文档或技术方案
2. 选择起稿模板或直接写正文
3. 多选想使用的知识库，填写可选优化要求
4. 点击“优化”，在差异中逐处合并或合并全部剩余建议
5. 继续编辑、再次优化，下载 Markdown

#### 需求追溯

1. 在左侧目录树中选择需求
2. 点击 Rail 栏"追溯"按钮
3. 查看需求时间线：创建、同步、分析等事件
4. 点击事件可查看详细信息

### 写作

侧栏“写作”支持需求文档、技术方案，浏览器草稿按工作区、项目路径、需求目录及文档类型隔离。切换新需求显示独立草稿，切回原需求恢复各自内容；知识库选择按工作区记忆。可从空白或内置结构起稿，已有正文不会被起稿按钮覆盖；保存到当前需求目录，同名文件需确认覆盖。内嵌图片自动落到该需求的 `assets/images/`，正文保留相对文件链接；相同图片按内容去重。编辑器及文件预览按当前需求读取附件，优化输入不包含图片 Base64，模型不能把未读取的图片内容当作事实。

多选全局知识库中的工作区分区后，输入正文和可选优化要求，点击“优化”。沿用当前 DSH 会话与 TaskExecutor 的 subagent 调用方式，要求 spawn provider 支持工具隔离。子代理仅能搜索所选库、分页读取冻结资料与提交候选，不会写文件或修改知识库；每个非空所选库至少完整阅读并引用一篇资料。候选返回来源路径和版本。未选择库时仅优化当前正文。

使用现有 DiffViewer 审阅整体与局部差异，可逐处合并、保留原文或合并全部剩余建议。审阅期间正文锁定，避免将旧建议覆盖到新版本；已合并修改即时保存，结束审阅后继续编辑和优化。优化任务支持取消，错误时草稿保留。关闭页面、切换工作区或需求目录不会取消后台任务；返回同一需求时恢复对应进度或待审结果，不恢复其他需求的任务。服务重启后的优化任务需要重新发起。

### 配置与操作入口

同步分析同时检查模型上下文容量和必读证据的分页工作量。未设置 `sync.maxAnalysisReadPages` 时，默认页数额度为模型可用输入预算除以 2048 后向上取整，限制在 24～128 页；例如 228729 tokens 对应 112 页。显式配置仍支持 8～128 页。大文件会无损拆为带来源位置的片段，不因超过单块读取工作量而丢弃内容。文档原文等公共必读输入较大时，实际页数额度会相应增加，仍受完整模型输入预算约束。

同步检查显示按统一多语言算法估算的代码正文量；分析阶段显示累计输入预算，并分别列出证据读取、重复公共材料、提示词和预留额度。预算包含封装与重复上下文，不代表代码量或模型实际消耗。每块的预算分解保存在任务状态及分块清单中。

代码分析、会话分析各自有多个分块时，仅启动一个汇总子代理读取该阶段全部分块的报告与变更索引，不再两两合并或递归启动汇总。只有一个分块时直接沿用其结果。汇总继续校验完整输入预算、证据引用及全部输入变更的去向，超限明确失败，不静默截断。

读取工具每页返回 `readState`，标明剩余必读项和精确续读位置。子代理提前结束时，插件通过 DSH 的 `agent/turn-stopping` 接口在同一子任务中有限次数提醒补读或补写；`sync.maxCompletionReminders` 默认 3，可配置为 0～5。完整读取、证据哈希、双输出及发布校验始终保留。每个分析阶段保存 `*.read-state.json`，用于核查实际读取范围和成功写入的输出，最终回复不能代替工具回执。

分析索引可直接通过 `req_hub_sync_write` 的 `content` 参数提交结构化 `{changes,pending}` 对象，工具负责 JSON 序列化；仍兼容旧的 JSON 文本，报告继续使用 Markdown 字符串。校验失败按字段返回错误码、路径、实际值及正确值或候选值，文档块 ID 错误不会再被误报为证据引用错误。`sync.maxInvalidOutputWrites` 默认 6，可配置为 1～20；达到无效写入上限时取消对应子代理并保留具体失败原因，不取消父任务或其他分块，也不放宽证据和发布校验。诊断文件记录无效写入次数及最后错误。

配置优先使用宿主 `profileContext.dir`，保存到 `<profileContext.dir>/req-hub/config.json`。独立运行时依次回退到 `<DSH_PROFILE_DIR>/req-hub/config.json`、`<DSH_HOME>/profiles/<DSH_PROFILE>/req-hub/config.json`，无 profile 时使用 `<DSH_HOME>/req-hub/config.json`。DSH_HOME 默认 `~/.dsh`。首次读取迁移安装目录中的旧配置并保留旧文件；损坏配置明确报错。Cordis `Config` 支持声明部署配置并校验，显式部署字段优先于界面保存的值。

HTTP 操作通过宿主 Connection 认证；`req_hub_action` 工具与页面调用同一 Host 实现，写作和分析使用工具调用方的真实会话，不能冒充另一会话。工具不暴露打开系统文件管理器等用户专属操作。

## 知识增强功能

在“设置 → 知识关联与代码索引”中启用。用户不再需要进入独立工作台选文档建图：

- 查看文档和搜索详情：根据当前文档自动提取同需求文档、明确依赖和引用，展示来源并可跳转；普通引用、内容相关和代码关联候选不当作已确认业务依赖。文档层关联按有效入库版本惰性重建，不启动模型或 GitNexus。超出完整分析预算明确提示，不静默截断后宣称完整。确认、拒绝和手工依赖折叠在当前文档中，重建保留审阅决定，来源改变后待复核。
- 结构检查：在本地检查标题、空章节和占位标记，不启动子代理，不按篇幅评分。
- 写作：按当前需求推荐资料，勾选后按精确版本加入原有受控知识检索；草稿检查读取当前未保存正文，正文改变后提示重新检查。语义检查与范例建议沿用隔离子代理，结果需审阅，不自动修改正文或全局 Prompt。
- 同步：在范围选择及已结束任务详情中展示关联影响与一致性检查。只有有效且已确认的业务关系用于影响传播；选中的关联文档仅作为只读参考，不扩大正式文档写入范围。无 GitNexus 时保留文档功能。
- 业务影响：默认只沿有效且已确认的显式/手工业务依赖传播；代码关联不会自动变成业务依赖。查询有节点、边、深度和输出预算，达到边界会标明截断。

GitNexus 是可选能力。先在 DSH 中配置 GitNexus MCP 服务，默认服务名为 `gitnexus`，可用 `enhancements.gitnexusServer` 调整。点击“刷新代码关联（MCP）”后，插件才通过 DSH Tools 的策略执行链调用 MCP `list_repos` / `impact`；按工作区真实路径、提交和工作树状态核对索引，不按项目同名匹配。没有 MCP、项目未索引、索引过期、工具拒绝或结果不完整时保留文档层结果，并展示降级状态。索引过期或未创建时可点击“更新索引”：Host 按 PATH 解析本机 `gitnexus` 命令，沿用命令自身的 Node 选择，执行 `gitnexus analyze --index-only --workers 2 --verbose`，不优先使用 DSH 的 Node；默认 Worker 启动等待为 60 秒，分别通过 `enhancements.indexWorkers` 和 `enhancements.indexWorkerReadyTimeoutMs` 配置，只处理当前工作区的 Git 仓库根目录，不安装软件、不改写项目说明或技能文件、不监听文件自动重建。界面展示真实阶段、CLI 提供的百分比（没有则显示不确定进度）及最近 50 条执行日志。支持取消并等待进程树退出，默认超时 30 分钟（`enhancements.indexTimeoutMs`）。CLI 完成后通过 MCP 检查状态；未提交改动或 MCP 缓存仍可能使状态显示过期，界面不会把索引进程成功当成 MCP 已确认可用。

同步保留原有“参考知识库”并支持勾选当前需求的关联文档。默认不选；手动勾选的资料先校验归属、有效性和精确版本，再与选定知识库召回结果去重，全文按版本冻结成 `knowledge.*` 只读 artifact。知识只解释背景和术语，引用单独记录在 `supportingKnowledgeRefs`，不能取代 `evidenceRefs` 中的代码/会话证据。全文超出可选上下文预算会明确失败，不截断正文。

增强配置位于 Host `Config.enhancements`：默认关闭、每工作区一个任务、全局最多两个任务；文档数量、输入/输出字节、查询节点/边/深度、超时及保留数量均受 schema 校验。新增 `enhancements.sqlite` 与全局知识库数据库同级，独立存储任务、版本化关系和人工决定，不复制全部源码；任务/构建修订有数量保留上限，审阅决定独立保留。无需迁移历史增强数据，也不会自动删除原文档、原会话或已入库知识。
