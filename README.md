# ReqHub

DeepSeek Harness 插件。

界面说明使用简短文案，避免重复字段信息及内部流程解释；保留必要限制、失败原因和处理方法。

设置页按“模型”“知识关联与代码索引”“Wiki 管理”“Prompt 管理”拆分标签，使用与日志页一致的
下划线导航及右侧关闭按钮，不再显示“设置”标题栏。切换标签保留未保存内容；Wiki 标签直接
显示维护配置与每日计划。模型与 Prompt 共用保存操作，知识关联和 Wiki 保留各自原有保存方式。

## 快捷同步

同步历史统一由顶部「同步历史」页签进入，保留类型筛选、版本对比、任务详情及删除操作。
历史页按「版本对比 / 执行记录」分区，类型筛选统一作用于两者；版本选择等宽，操作单独对齐。版本菜单与选择框同宽对齐，圆角、间距及浮层材质遵循 DSH 规范。
「查看差异」直接打开只读对比并保留返回焦点；记录的详情和删除操作分组，存储清理默认收起。
「删除本次记录」仅清理一次执行；「删除任务全部记录」清理同一任务的所有执行（含重试）。两者均保留正式文档。
差异页按「结果摘要 / 版本信息 / 内容差异」排列，支持仅看变更；无差异时顶部提示，正文默认折叠。窄面板按版本上下排列，保留源码行格式与横向滚动。
同步面板使用与日志页一致的「快捷同步 / 自定义同步 / 同步历史」页签，移除原有的「同步文档」标题栏。
快捷同步输入时匹配当前工作区的本地功能分支，必须从候选列表选中后才能开始；
支持方向键、Enter 选择和 Escape 关闭，修改文本后需重新选择。
可同步的分支遵循命名格式（`feature/开发者/YYYY-MM-DD-需求标题`），复用目录创建接口，
首先校验分支属于当前工作区仓库，拒绝借用父目录仓库；目录存在时直接使用。
与本地 `main`（不存在时使用 `master`）比较，两者均不存在则停止，不切换或创建 Git 分支，
不纳入未提交改动，不改动暂存区及源码文件，仅创建需求目录和生成文档。
随后复用现有提交选择及分阶段同步流程，不选择会话，先同步需求文档，
Host 持有同一个执行名额，成功或确认已同步后再同步技术方案。前端仅提交一次请求并观察状态，
切换页面、关闭面板或连接中断不影响 Host 继续执行。失败、取消、删除或插件卸载会阻止后续阶段。
两份文档保存同一个快捷同步 ID；连接中断后可按此 ID 观察整个流程，而非只观察需求文档。
Host 重启不自动恢复执行；任务状态从文档记录重建，中断时需重新发起，已完成文档由原同步逻辑跳过。
自定义同步保留文档类型、提交、知识上下文及会话选择。切换页签保留当前进度。

需求文档和技术方案的自定义同步设置共用「同步目标 / 代码范围 / 参考资料 / 会话来源」
四个分区，统一标题、字段和操作对齐。参考知识库两类文档均可选择，需求基准仅在技术方案中
显示。会话来源默认收起并显示已选数量，展开后通过 DSH / Codex 标签切换，保留各自的
筛选和选择；来源对应的刷新、管理及预览操作继续保留。底部常驻选择汇总和开始按钮，
窄面板下字段与操作自动纵向排列；原有同步校验及执行流程不变。

技术方案同步的代码与会话分析支持需求基准参考。自定义同步可搜索当前需求目录及子目录内的
文件，选定一项才生效，清空可取消；未选时沿用原同步流程。快捷同步固定使用本轮成功发布的
`requirement.md` 内容快照，不受随后对需求原文的编辑影响；需求阶段已同步而跳过时使用当前
需求文档。快捷同步不接受自定义参考覆盖。PDF、Word、Excel 复用现有解析器，其他文件须为
可读取的 UTF-8 文本；不可解析或超出读取预算时明确失败。

参考正文完整冻结为必读 artifact，代码和会话分析都需完整读取。它限定业务范围，但不能充当
实现证据。技术方案仍沿用技术文档结构，描述职责、架构、接口、数据流、约束与失败处理，
不会改写为需求文档。需求与实现冲突或缺少实现证据时列为待确认事项。参考路径和内容版本
参与同步去重，参考发生变化时会重新分析，即使所选 Git 提交没有变化。

同步页的「参考知识库」仅提供名称搜索、勾选、清空及刷新。同步时沿用 Host 的受控检索，
按当前需求从所选知识库获取相关资料；不选则不增加知识参考。知识库补充背景、术语和已有
约定，不替代需求基准、代码或会话证据，也不修改知识库内容。「关联影响与一致性审阅」
从同步设置和任务详情移除，相关检查及审阅能力保留在知识库中。

同步中的 Codex 工作区按当前项目的文件夹路径自动匹配，不提供切换入口。会话读取、刷新和
同步提交均校验路径归属，历史绑定及客户端传入的其他 Codex 工作区 ID 不能改变匹配结果。
没有匹配会话时显示空态；匹配多个工作区时明确提示，不猜选，也不影响仅使用代码或 DSH 会话同步。
DSH 与 Codex 会话按最近更新时间倒序展示，无更新时间时使用创建时间。
来源标签显示当前工作区会话总数与已选数，筛选不改变统计。
不可选会话淡化显示，并标明「无完整轮次」「读取失败」或「未就绪」；可读取的内容仍支持预览。

快捷同步和自定义同步共用的分析阶段保留 Markdown 报告与 JSON 索引两个产物。
报告只写简短总览、跨项风险及知识来源版本，变更明细与未决事项集中保存在 JSON 中。
汇总阶段仍完整读取各分析报告与索引，原文和提交清单按需读取；编辑阶段读取候选正文，
避免再读一份相同原文。连续编辑复用工具返回的候选哈希，需要定位文本时再读候选。
子代理数量、证据完整性、变更保留、精确编辑、版本及发布校验保持不变。

## Prompt 与输出语言

13 个内置任务模板使用英文，并遵循 `asd-ste100` 的清晰表达规则。模型的过程说明、进度、
同步分析报告、变更索引及任务完成回执使用英文。同步编辑阶段将英文建议转换成最终文档语言。
写作的 `overview` 使用英文，`content` 是最终文档；Wiki 页面、摘要、问答与知识检查结果属于
最终交付内容。内部 Wiki 维护规则使用英文，供后续模型任务读取。

最终交付语言优先采用用户明确指定的语言，否则保留输入文档语言，再参考来源资料或问题语言；
无法判断时使用简体中文。原文引用、代码、路径、标识符和协议字段保留原样，不翻译无关正文。
统一语言约束在执行时加入，绑定、未绑定或无法加载 Skill 时均生效。已保存的自定义模板不会被
覆盖，执行时同样附加语言约束。语言约束依赖模型遵循，仍需在真实任务中检查输出。

## Wiki 自动维护与运行事件

在「编写」面板或文档编辑器保存文档后，ReqHub 只接入来源正文、保存版本并标记 Wiki 待更新，
默认不调用模型。仅「知识库 → Wiki」页顶部展示「更新 Wiki（数量）」与运行事件入口，显示当前范围内有多少篇文档
待整理。数量按每篇已入库且可读取文档的最新版本计算，包含失败、取消和中断后待重试的文档；
旧版本、缺失或不可读取的来源不重复计入。问答、来源状态查询和数量统计不会启动整理任务。

点击「更新 Wiki」后，Host 将本次选中的待更新版本持久化排队，逐篇调用模型，生成后自动发布
或保留人工审核候选。任务执行期间再次保存的新版本需要下一次更新，不会擅自扩大本批次范围。
保存、等待会话、排队、处理、待审核、发布和失败分别显示；失败不会撤销已经保存的文档。
没有可用的同工作区 DSH 会话时，手动更新保留等待状态，会话创建后继续处理。

「维护 → 配置」可选择开启自动整理，默认关闭。开启后默认静默等待 30 秒；期间的新版本会重置
等待时间，只处理最新版本。可设置 `autoManageDelayMs`，设为 0 时立即整理；已有显式自动整理设置
继续保留。关闭或卸载插件会清理定时器并取消、等待已启动任务。

「维护 → 配置 → 每日定时更新 Wiki」可独立启用每日计划，设置 `dailyUpdateTime`（24 小时制
`HH:mm`）和 `dailyUpdateTimeZone`（IANA 时区，默认北京时间 `Asia/Shanghai`）。启用后按该时区
每天处理所有仍可访问的已接入知识库的待更新资料；不要求开启“来源保存后自动维护”。
计划默认关闭，未启用时不会产生定时更新任务。

调度由正在运行的 DSH 宿主持有，按分钟检查到期时间。同一知识范围同一日期只触发一次，
该次触发记录与来源入队在一个事务中保存，重启不会重复排队。没有待更新资料时只记事件，
缺少可用会话时保留等待队列；任务失败后保留待更新数量，可手动重试。宿主重启可补触发当天
漏掉的一次，不追补历史日期。新启用或改时间后，如果当天执行时间已过，从下一天开始；当天
已经触发过的范围不会因改时间再次自动触发。关闭计划会停止后续触发，已入队任务仍继续执行。
触发、无变化、失败及后续执行详情均在「Wiki 运行事件」中查看。

「日志 → Wiki 运行事件」与「知识库 → 维护 → Wiki 运行事件」提供相同的持久化事件视图。
可按任务 ID 筛选、自动刷新、加载更早记录、展开事件详情。事件覆盖来源接入、执行阶段、
子会话 ID、模型请求、证据分段读取、结果提交校验、版本复核、生成、发布、取消与失败。
运行记录保存在知识库 SQLite 中，与可清空的应用内存日志分开；不记录原文正文或模型思考。
事件按当前知识范围隔离，跨工作区查看须切换工作区。

执行器错误保留原始错误码、停止原因与诊断；模型结束但未提交有效结果时才报告
`WIKI_RESULT_INCOMPLETE`。诊断展示最多 4000 字符，并标记是否截断；子会话 ID 用于进一步排查。
旧任务没有保存的详细步骤无法追溯补齐，可在维护任务列表查看已有错误，选择重试后记录新事件。
重试仍需可用会话和有效证据；人工编辑受影响时需在审核区确认候选。
模型结束前若尚未成功提交，Host 最多提醒三次在同一轮完成读取、修正并提交；取消、关闭或已成功
提交的任务不会收到提醒。提交被拒后未重交时，保留具体校验错误及字段路径，不以结果不完整覆盖。
来源摘要分类只接受 `requirement`、`design`、`cr`、`other`，需求分类不使用 `requirements`。
自动入库、重新生成和健康检查无需额外填写指令，默认遵循当前维护规则；问答必须填写问题。

Wiki 读取回执区分来源、Wiki 页面与控制文档，并提供原文总行数。`rules` 和 `index` 必读，
但不能生成来源摘要或作为业务证据；关系类型限定为 `related`、`depends_on`、`contradicts`、
`supersedes`。提交不合法时，工具回执及「提交校验失败」事件包含具体字段 `path`、原因
`reason` 和修正所需的版本、行数或允许值，便于模型修正和人工排查；不保存提交正文。
新增 Wiki 页面使用 `entityKey`，更新已有页面使用完整读取后的 `pageId`。
读取回执及索引提供裸页面 ID，同时兼容 `wiki:<pageId>` 证据别名；来源文档 ID 不能当作页面 ID。
关系端点仅接受本次生成的页面键或完整读取的已有 Wiki 页面，提交时即校验，发布时再次校验作用域。

## 新建功能

点击侧边栏「新建」按钮或按 `Ctrl+N` 打开新建面板。系统会读取当前 Git 分支名，自动填充表单字段。

### 场景一：手动新建需求目录

当前分支名符合 `feature/<开发者>/<日期>-<标题>` 格式时，表单自动填充开发者、日期和标题。可选勾选「同时新建 Git 分支」从当前 HEAD 创建新分支。

**浅色主题 - 窄屏 (400px)**：

![新建表单 - 浅色窄屏](docs/create-form-light-narrow.png)

**深色主题 - 宽屏 (900px)**：

![新建表单 - 深色宽屏](docs/create-form-dark-wide.png)

**深色主题 - 窄屏 (400px)**：

![新建表单 - 深色窄屏](docs/create-form-dark-narrow.png)

**涉及功能**：

- 状态预检（`/create-status`）— 读取 Git 分支、HEAD、未提交修改和中间状态
- 分支名自动填充 — 解析 `feature/<开发者>/<日期>-<标题>` 格式
- 可选新建 Git 分支 — 从当前 HEAD 创建并切换
- 预览路径 — 实时显示将创建的目录和分支名
- 确认对话框 — 勾选新建分支时弹出确认
- 创建后自动选中 — 刷新目录树并选中新建的需求

### 场景二：在 main/master 分支新建

当前处于 main/master 分支且无未提交修改时，表单顶部额外显示「拉取并合并远端」按钮，可先更新主分支再新建。

**涉及功能**：

- 更新主分支（`/update-main`）— 校验 HEAD → 查找远端 → fetch → fast-forward merge
- 冲突处理 — 分支或文件已变化、无远端、拉取失败、无法快进分别报错
- 更新后刷新 — 成功后重新检查状态，继续新建操作

### 场景三：定位会话需求（分支名不规范）

点击顶栏「定位」按钮，系统根据当前 DSH 会话的工作目录自动定位工作区。如果分支名不符合规范，跳转到新建表单并提示用户。

**涉及功能**：

- 获取当前 DSH 会话 — 从 `window.__DSH_CTX__` 读取会话 ID
- 匹配工作区 — 按完整路径匹配已注册工作区
- 分支名解析 — 支持多种格式（`feature/<开发者>/<日期>-<标题>` 等）
- 不符合规范时跳转 — 清空选择，打开新建表单，勾选「新建分支」
- 符合规范但目录不存在 — 弹出确认对话框，确认后创建目录

### 场景四：浏览已有需求目录

点击顶栏「选择需求」按钮，弹出需求目录浏览窗口，按开发者分组显示所有需求。

**涉及功能**：

- 树形展示 — 开发者节点可展开/折叠，显示需求数量
- 需求项展示 — 显示日期、标题、文件数
- 选中高亮 — 当前选中的需求高亮显示
- 点击选择 — 选中后关闭弹窗，切换到该需求

- 工作区列表 — 列出所有已注册工作区
- 切换后清空选择 — 清空开发者和需求选择，保存配置
- 重新检查创建状态 — 切换后重新拉取 `/create-status`

### 场景六：已有需求拦截

如果当前分支名已匹配一个存在的需求目录，点击「新建」时弹出「当前需求已创建」通知，显示分支名和目录路径，不打开表单。

**涉及功能**：

- 已有需求检测 — 在 `/create-status` 中检查分支名是否匹配已存在目录
- 拦截通知 — 弹出对话框显示分支名和目录路径
- 提示更换工作区 — 如需新建其他需求，需先切换工作区
